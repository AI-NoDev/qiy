# 多语言（messages / i18n）

Qiy 的界面文案分三层，全部通过同一个 `messages` 块和同一套 key 规则解析：

1. **模型派生 key**：资源、字段、枚举、菜单、图表、Dashboard、命令等标签自动获得稳定 key，词典缺失时回退 DSL 原文。
2. **内置 chrome 词典**：生成页面自身的按钮、状态、主题控件、登录/回调页、功能总览、API 文档、访问密钥等文案，内置 zh-CN / en-US 两套，可用同名 `qiy.*` key 覆盖。
3. **Refine / Ant Design 官方 key**：`buttons.*`、`notifications.*`、`actions.*`、`pages.login.*` 等，注入同一 i18n provider，项目 `messages` 也可以覆盖。

本文是 `messages` 与生成 i18n 运行时的完整参考；模型 label 的概览见 [DSL 总览 · 消息与模型描述](/dsl/overview#消息与模型描述)。

## 语法

`messages` 块写在 `application {}` 内，位置是**固定**的：`env` 之后、`permission` / `workflow` / `enum` / `entity` 之前。

```qiy
qiy v0;

application reviews-admin {
  database sqlite {}

  messages {
    default "zh-CN";
    locale "zh-CN" {
      "qiy.resources.reviews.label" "审核单";
      "qiy.resources.reviews.fields.note.label" "说明";
      "qiy.enums.reviewState.values.pending" "待审核";
      "review.note" "请说明审核决定";
    }
    locale "en-US" {
      "qiy.resources.reviews.label" "Reviews";
      "qiy.resources.reviews.fields.note.label" "Note";
      "qiy.enums.reviewState.values.pending" "Pending";
      "review.note" "Explain the decision";
    }
  }

  enum reviewState {
    value pending;
    value approved;
  }

  entity reviews @label("Reviews") {
    field id UUID @id;
    field note Text @label("Note") @comment(t("review.note"));
    field state reviewState;
  }
}
```

### 词法与块结构

```text
messages {
  default "<locale>";                 // 必须是块内第一条，且只有一条
  locale "<locale>" {                 // 可重复，顺序任意
    "<key>" "<value>";                // 每条以 ; 结束
    ...
  }
  ...
}
```

- `messages`、`default`、`locale` 都是小写关键字。
- `default` 和 `locale` 的值必须是**带引号**的字符串。
- key 与 value 都必须是带引号的字符串；value 里的 <code v-pre>{{name}}</code> 由 i18next 插值。
- key 允许点号（`qiy.resources.users.label`），因为生成器把 `keySeparator` 设为 `false`，点号是字面字符而不是嵌套层级。
- 同一个块内 `locale` 不能重复；同一个 locale 内 key 不能重复。
- 块内除 `default` / `locale` 之外的 token 会报 `Expected locale`。

### include 片段

`messages` 可以拆到单独文件，用选择器只导入消息块：

```qiy
include "modules/messages.qiy";
include "modules/messages.qiy" @messages;   // 只导入该文件唯一的 messages 块
include "modules/messages.qiy" @message;    // 兼容别名
```

选择器要求目标文件**恰好一个**顶层 `messages` 块；没有块或多块都会报错。

## 参数表

| 元素 | 必填 | 取值 | 说明 |
| --- | --- | --- | --- |
| `default "<tag>"` | **是** | 规范 BCP 47 语言标签 | 默认语言；必须存在同名 `locale` 块 |
| `locale "<tag>"` | 至少一条（default 本身） | 规范 BCP 47 语言标签 | 每种语言一个块；块内是 key/value 字典 |
| key | — | `^[a-zA-Z_][a-zA-Z_0-9.-]*$` | 不能含空格、`:`、`/`，不能以数字开头；不能含 `__proto__` / `prototype` / `constructor` 段 |
| value | — | 任意字符串 | 支持 i18next 插值与复数后缀 |

### 语言标签校验

生成器用 `Intl.getCanonicalLocales(locale)[0] !== locale` 判断，因此必须是**已经是规范形式**的标签：

| 接受 | 拒绝 | 原因 |
| --- | --- | --- |
| `zh-CN`、`en-US`、`ja-JP`、`fr-FR`、`ar-EG`、`zh-Hans`、`es-419` | `fr_fr` | 下划线不是 BCP 47 分隔符 |
| `ja`、`de`（仅语言） | `FR-fr`、`en-us`、`zh-hans` | 大小写不规范，canonical 形式不同 |

拒绝时报 `Invalid message locale <tag>: use a canonical BCP 47 language tag`。

## 默认值与校验

- **不写 `messages`**：默认语言为 `zh-CN`，`projectMessages` 为空；界面仍完整可用（内置 chrome + DSL 原文回退）。
- **写了 `messages`**：`default` 必须指向一个已声明的 `locale` 块，否则报 `Missing default message locale <tag>`。
- `default` 缺失、重复或不在块首：解析失败。
- 未知语言、非规范标签：`Invalid message locale ...`。
- 重复语言：`Duplicate message locale <tag>`。
- 非法 key：`Invalid message key <key>`。
- 重复 key：`Duplicate message key <locale>.<key>`。
- 引用了不存在的默认语言消息（`@comment(t("key"))`、`@label(t("key"))`、`@error(t("key"))`、`@confirm(t("key"))` 等）：`Missing default locale message for <purpose>: <key>`。`purpose` 会指出是 application/database/enum/field/menu/action 等哪类描述。
- 位置错误（例如把 `messages` 写到 `entity` 之后）：解析器在固定槽位之外遇到它，通常报 `Expected } near token <n>` 或 `Expected <end>`。

## 生成结果

```text
apps/web/app/messages.ts             # defaultMessageLocale + projectMessages + projectMessage()
apps/web/app/i18n.ts                 # 内置 chrome/Refine 词典、语言解析、i18next provider、qiyApiError 用的 locale
apps/web/app/root.tsx                # 语言状态、document.lang/dir、Header 语言下拉
apps/web/tests/model-i18n.test.ts    # 模型派生 key 稳定性与词典解析
apps/web/tests/chrome-i18n.test.ts   # 内置 chrome 键中英文完整性
apps/web/tests/project-messages.test.ts # 项目词典、默认语言、原型污染与语言切换
```

- `messages.ts` 原样保存 `messages` 块；`projectMessage(locale, key)` 负责"当前语言 → 默认语言 → undefined"。
- `i18n.ts` 负责把 chrome/Refine/项目词典合成 i18next 资源，并暴露 `supportedLocales`、`languageOptions`、`resolveLocale`、`readStoredLocale`、`storeLocale`、`t`、`filterModeLabel`、`getAntdLocale`、`createI18nProvider`。
- 生成的 `messages` 不会写回服务端数据库；REST/GraphQL 描述使用默认语言。

## 模型派生 key（自动翻译键）

生成器只为**声明的标识符**派生 key，不依赖 label 文案。改 label 不会让翻译失效，改标识符（实体/字段/枚举/组名/图表名/命令名）会换 key。

| key | 覆盖的界面文案 | 回退 |
| --- | --- | --- |
| `qiy.resources.<resource>.label` | 资源基础名；关联记录卡片直接使用，同时作为 `.singular`/`.plural` 的后备 | 实体 `@label` → 实体名 |
| `qiy.resources.<resource>.singular` | 单数标题（新建/编辑/详情/抽屉） | `@singular` → `.label` 词典 → `@label` → 实体名 |
| `qiy.resources.<resource>.plural` | 复数标题（列表、菜单节点、`viewResource` 插值） | `@plural` → `.label` 词典 → `@label` → 实体名 |
| `qiy.resources.<resource>.fields.<field>.label` | 列头、详情字段名、表单 label、筛选/关系列头、统计卡字段名 | 字段 `@label` → 字段名 |
| `qiy.enums.<enum>.label` | 枚举说明（详情/提示） | 枚举名 |
| `qiy.enums.<enum>.values.<value>` | 枚举 Tag、下拉选项、分布图例 | 枚举值 `label` → 值名 |
| `qiy.menu.<group>.label` | 侧边栏分组、自动创建的系统管理分组 | 分组 `@label` → 组名 |
| `qiy.dashboard.<metric>.label` | 旧 `dashboard { metric ... }` 指标卡标题 | `@label` → 指标名 |
| `qiy.charts.<chart>.label` | 图表卡片标题 | chart `title` → chart 名 |
| `qiy.charts.<chart>.views.<kind>.label` | 视图内部标题（kind = `const`/`pie`/`bar`/`line`/`table`） | 视图 `title` → chart `title` → chart 名 |
| `qiy.charts.<chart>.labels.<value>` | 分布数值文案覆盖（同一 chart 的所有视图共享） | 显式映射/枚举 value label → 原始值 |
| `qiy.charts.<panel>.label` | 图表 panel 标题与下拉选项 | panel `title` → panel 名 |
| `qiy.actions.<action>.label` | 业务命令按钮 | Action `label` → Dataflow `@label` |
| `qiy.actions.<action>.confirm` | 命令确认文案 | Action `confirm` → Dataflow `@confirm` |
| `qiy.actions.<action>.inputs.<input>.label` | 命令表单字段 | 输入 `@comment(t("..."))` → 输入名 |
| `qiy.dataflows.<dataflow>.label` | 功能总览页的 Dataflow 名称 | Dataflow `@label` → 流程名 |

### `<resource>` 是表名，不是实体名

`<resource>` 使用**路由/表名**（`entity <Name> table <table>` 的 `<table>`；未写 `table` 时即实体名）。因此：

```qiy
entity Product table products { ... }
```

的翻译 key 是 `qiy.resources.products.label`、`qiy.resources.products.fields.name.label`，**不是** `qiy.resources.Product.title`。菜单、图表、命令、数据端点在生成代码里也都使用表名。

### 关联记录卡片

详情页的"关联记录"卡片没有独立 key：它复用来源资源的 `qiy.resources.<sourceTable>.label`。

### 命令输入与枚举选项

- Action 输入 label 优先使用 Dataflow input 的 `@comment(t("key"))`；没有时用 `qiy.actions.<action>.inputs.<input>.label`。
- 命令表单里的枚举输入选项使用 `qiy.enums.<enum>.values.<value>`。
- `@confirm(t("key"))` 会保留 key；`@confirm("text")` 使用 `qiy.actions.<action>.confirm`。

### 权限模型的 label

`permission field/group/verification` 的 `@label` 是**可选文档/i18n 元数据**，生成器**不会**为它们自动派生 key：

```qiy
permission field ApiGetUserPermission "api:getUser" @label(t("permission.apiGetUser"));
permission group operator { ApiGetUserPermission }
```

- 写 `@label("Read user API")`：只作为字面量，随当前语言保持不变。
- 写 `@label(t("permission.apiGetUser"))`：key 必须在默认语言中存在，生成 IR 保留 key，功能总览页按当前语言解析。
- 同理，`permission verification` 的 label 也只在使用 `t(...)` 时翻译。

### 业务错误 key

`@error(...)` 支持字面量与消息 key：

```qiy
step validate {
  require purchaseOrder.status == "approved" @error(t("errors.purchaseOrder.notApproved"));
}
```

生成命令在失败响应中返回 `{ error: "<默认语言文案>", errorKey: "errors.purchaseOrder.notApproved" }`；Web 端 `qiyApiError` 用**当前界面语言**查 `projectMessage(locale, errorKey)`，缺失时回退默认语言、再回退 `error` 原文。错误 key 不限定前缀，但推荐 `errors.*`。

### 注释与文档

`@comment(t("key"))` 在**解析时**用默认语言解析出文案（缺失即报错），同时把 key 保留在 IR：

- 生成源码注释、REST OpenAPI 描述、GraphQL 描述使用默认语言文案；
- 界面（字段提示、命令说明、图表/菜单说明）在运行时按当前语言重新解析 key。

因此 `t("key")` 引用的 key 必须写在**默认语言**块里，否则模型无法生成。

| `apiKey.curlTitle` / `apiKey.apiDocsLink` / `apiKey.searchPlaceholder` | 使用说明与搜索 |
| `apiKey.status.all` / `apiKey.status.active` / `apiKey.status.revoked` / `apiKey.status.expired` / `apiKey.never` | 状态筛选 |
| `apiKey.roleTooltip` / `apiKey.permissionTooltip` / `apiKey.groupTooltip` | 权限标签提示 |

### Refine / Ant Design 键

生成的 `app/i18n.ts` 预置了 Refine 的 `buttons.*`、`actions.*`、`table.actions`、`notifications.*`、`pages.login.*`、`pages.error.*`、`autoSave.*` 等中英文键。项目 `messages` 可以直接覆盖它们（例如 `"buttons.save" "保存"`、<code v-pre>"notifications.createSuccess" "{{resource}} 已创建"</code>）。

## 回退链

### `translate(key, options, fallback)`

Refine 的 `I18nProvider.translate` 由 `createI18nProvider(locale)` 实现；每种界面语言只构造一次 i18next 实例，资源合并顺序（后者覆盖前者）是：

1. 该语言的 Refine/AntD 官方键（`refineMessages`，zh-CN 或 en-US）；
2. 该语言的内置 chrome 词典（`localeMessages`，所有值加 `qiy.` 前缀）；
3. **默认语言**的项目 `messages`；
4. **当前语言**的项目 `messages`。

于是实际解析顺序为：

1. 当前语言的 `messages`；
2. 默认语言的 `messages`；
3. 内置 chrome / Refine 词典（中文语言用中文，其他语言用英文）；
4. 调用方传入的 `fallback`（即 DSL 里声明的原文）。

任何一层缺失都不会报错，最差回退到 DSL 原文，所以**没有 `messages` 的项目行为与旧版本一致**。

### 第三种语言会漏英文 chrome

因为第 3 层对所有非 `zh-CN` 语言都注入**英文** chrome，所以新增 `ja-JP` 等语言时，只翻译业务 key 会出现"业务中文、按钮英文"的混合界面。要完全本地化，需要在对应 locale 块里补齐要覆盖的 `qiy.*` 键。

### 其他辅助函数

| 函数 | 行为 |
| --- | --- |
| `projectMessage(locale, key)` | 当前语言 entries → 默认语言 entries → `undefined`（不做内置回退） |
| `t(locale, key)` | 先查项目 `qiy.<key>`，再查内置 chrome 词条 |
| `filterModeLabel(locale, mode)` | 项目 `qiy.filters.mode.<mode>` → 内置筛选词条 → mode 原文 |
| `resolveLocale(value)` | 已声明语言原样返回，否则返回 `defaultMessageLocale` |
| `readStoredLocale(fallback, storage)` / `storeLocale(locale, storage)` | `localStorage` 键 `qiy.locale`；读写异常静默回退 |
| `getAntdLocale(locale)` | 精确匹配已加载的 AntD 语言包，否则英文包 |

### 语言选择与持久化

- 语言下拉的选项来自 `supportedLocales`：固定包含 `zh-CN`、`en-US`，再并入 `messages` 声明过的语言（去重）。
- 选项显示名由 `Intl.DisplayNames([locale], { type: "language" })` 生成（各语言的自称）。
- 选择写入 `localStorage` 的 `qiy.locale`；刷新后 `readStoredLocale()` 恢复，未知值回退默认语言。
- 切换语言同时更新 Refine i18n、Ant Design `ConfigProvider` locale、`document.documentElement.lang` 与 `dir`。
- 服务端渲染时没有 `localStorage`，首屏用默认语言；客户端 hydration 后切到已存语言，可能出现一次文案切换。生成的 `Layout` 里 `<html lang="zh-CN">` 是静态骨架，客户端会覆盖 `lang`/`dir`。
- RTL：语言前缀为 `ar`、`fa`、`he`、`ur` 时设置 `dir="rtl"`，抽屉/侧边栏方向与 AntD `direction` 一起切换。

### Ant Design 语言包 {#ant-design-locales}

生成器只为以下**精确标签**追加 AntD 语言包导入（其余标签的 AntD 组件回退英文，但业务文案仍按 `messages` 翻译）：

`ja-JP`、`ko-KR`、`fr-FR`、`de-DE`、`es-ES`、`pt-BR`、`ru-RU`、`ar-EG`、`hi-IN`、`it-IT`、`zh-TW`。

例如 `ja` 与 `ja-JP` 的业务文案都能工作，但只有 `ja-JP` 会带来 AntD 日文分页/日期组件。要获得完整组件本地化，请使用上表中的完整标签。

## 复数与插值

- 插值语法是 i18next 的 <code v-pre>{{name}}</code>；`escapeValue: false`，值按纯文本插入（不会转义 HTML，**不要**把用户输入当 HTML 拼接）。
- 复数使用 CLDR 后缀：`_one`、`_other`、`_few`、`_many` 等，调用 `translate("cart.items", { count })`。生成器会为同时声明 `_one` 与 `_other` 的语言生成 `Intl.PluralRules` 断言。
- `translate(key, "default message")` 的第二参数字符串形式等价于传入 `defaultValue`。
- `keySeparator: false` 与 `nsSeparator: false`：key 中的 `.` 和 `:` 都是普通字符，不会被当成嵌套或命名空间。
- `translate` 会拒绝包含 `__proto__` / `prototype` / `constructor` 段的 key，直接返回 fallback，避免原型污染。
- 内置 `requiredWithLabel` 是唯一例外：它由 Ant Design 表单的 `validateMessages` 使用，占位符是 AntD 的 `${label}`；覆盖时请保留 `${label}`。

```qiy
locale "zh-CN" {
  "cart.items_one" "{{count}} 件商品";
  "cart.items_other" "{{count}} 件商品";
  "users.greeting" "你好，{{name}}";
}
locale "en-US" {
  "cart.items_one" "{{count}} item";
  "cart.items_other" "{{count}} items";
  "users.greeting" "Hello, {{name}}";
}
```

## 主题与界面文案

主题/色彩模式控件本身也走 chrome 词典：

- 主题名 key 由 `"qiy.theme" + Key` 动态拼接：`qiy.themeBlue`、`qiy.themePurple`、`qiy.themeGreen`、`qiy.themeOrange`、`qiy.themeRed`。
- 控件无障碍标签：`qiy.themeColor`、`qiy.colorMode`；模式选项：`qiy.colorLight`、`qiy.colorDark`、`qiy.colorSystem`。
- 语言选择器：`qiy.language`；个人中心入口：`qiy.profile`。
- 生成的个人中心与登录页文案（`qiy.profileTitle`、`qiy.signOut`、`qiy.otp*`、`qiy.oidc*` 等）同样可被项目 `messages` 覆盖。

主题注册表、持久化键与暗色模式细节见 [UI 与主题](/guide/ui-theming)。

## 文档页面文案

`features` 打开后生成的三个系统管理页面（功能总览 `/system/overview`、API 文档 `/system/api-docs`、访问密钥 `/system/api-keys`）使用独立的 chrome 分组：

- `qiy.docs.*`：功能总览页签、实体/关系/Dataflow/权限模型表头、Mermaid 失败提示、OpenAPI 浏览区。
- `qiy.apiDocs.*`：API 文档页标题、权限/认证 Tooltip、搜索与空结果。
- `qiy.apiKey.*`：访问密钥页与列表/创建/撤销/一次性密钥提示。

侧边栏链接文案分别复用 `qiy.docs.title`、`qiy.apiDocs.title`、`qiy.apiKey.title`。这些页面本身按当前账号权限过滤内容，但页面入口对任意已登录用户可见。

## 添加一种语言

1. 在 `messages` 中增加 `locale "<tag>" { ... }`，至少覆盖要翻译的业务 key。
2. 确认标签是规范 BCP 47（`ja-JP`、`de-DE`、`pt-BR`……）且未重复。
3. 如需 AntD 组件本地化，使用[支持列表](#ant-design-locales)中的精确标签。
4. 若默认语言也要换（例如以 `en-US` 为默认），把 `default "en-US"` 指向存在的块，并确保所有 `t("key")` 引用都在 `en-US` 块里。
5. 需要 RTL 时使用 `ar-EG`/`fa-IR`/`he-IL`/`ur-PK` 等标签；方向由语言前缀自动推导。
6. 重新生成后，`supportedLocales` 会自动包含新语言，语言下拉即可切换。
7. 生成测试 `model-i18n.test.ts` 会遍历所有模型 label 断言 key 稳定与词典解析；`chrome-i18n.test.ts` 断言内置 chrome 键在中英文下都存在。新增语言建议补一份完整词典并运行生成项目的 `bun test`。

## 最佳实践

- **同时声明 `.label`、`.singular`、`.plural`**：菜单项优先使用 `.plural`，缺失时回退 DSL `@label` 原文（不会自动回退到 `.label` 词典），只写 `.label` 会出现"菜单是英文、标题是中文"的混搭。
- **key 用表名**：`entity X table y` 的翻译写在 `qiy.resources.y.*`。
- **不要为了改文案去改 key**：key 由标识符派生，改标识符会让旧翻译全部失效。
- **默认语言必须自洽**：所有 `t("key")` 引用都要在默认语言块中存在，否则模型直接生成失败。
- **第三种语言补齐 chrome**：至少覆盖 `qiy.new/edit/delete/save/cancel/search/noData/paginationTotal`、主题控件、登录页与文档页分组，否则会漏英文。
- **业务错误用 key**：`@error(t("errors...."))` 让错误随界面语言切换；直接写字面量只保留默认语言。
- **命令输入说明优先用 `@comment(t("key"))`**：它会同时成为 Action 输入 label 的 key。
- **复数只在需要时使用**：没有 `_one`/`_other` 的 key 按普通字符串处理；中文通常一个形式即可。
- **不要写危险 key**：`__proto__`、`prototype`、`constructor` 会被拒绝或忽略。
- **保留 `${label}`**：覆盖 `qiy.requiredWithLabel` 时使用 AntD 占位符。

## 校验错误速查

| 报错 | 触发 |
| --- | --- |
| `Invalid message locale <tag>: use a canonical BCP 47 language tag` | 语言标签非规范形式 |
| `Duplicate message locale <tag>` | 同一语言两个 `locale` 块 |
| `Missing default message locale <tag>` | `default` 没有对应块 |
| `Invalid message key <key>` | key 不匹配 `^[a-zA-Z_][a-zA-Z_0-9.-]*$` 或含危险段 |
| `Duplicate message key <locale>.<key>` | 同一语言重复 key |
| `Missing default locale message for <purpose>: <key>` | `t("key")` 在默认语言中不存在 |
| `Expected locale` | `messages` 块内出现未知 token |
| `Expected } near token <n>` | 块位置错误或括号不匹配 |
