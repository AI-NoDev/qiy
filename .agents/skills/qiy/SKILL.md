# Qiy

Qiy turns a declared `.qiy` model into editable TypeScript: a Refine + React Router admin, a Bun + Elysia REST/GraphQL API, a Drizzle database layer, tests, OpenWiki docs and deployment examples. Work from the public `qiy` CLI and `.qiy` files; never require Qiy generator source, MPS models or private repository internals.

## Use this skill when

- The user wants to create, extend, review or update a Qiy application.
- The user has a `.qiy` model or asks about Qiy DSL blocks: entities, fields, relations, enums, permissions, dataflows, actions, charts, menus, messages, auth, storage, realtime, scope/restrict, pages.
- The user mentions `qiy create`, `qiy init`, `qiy generate --sync`, `qiy skill install`, or an existing generated workspace.
- The user wants an admin/CRUD app generated from a model instead of hand-written boilerplate.

## Do not use this skill when

- The task is about a different framework and does not involve `.qiy` or the Qiy CLI.
- The user needs Qiy compiler internals or wants to modify the generator itself (that is maintainer work, not this skill).

## Choose a workflow

- New standalone project: `qiy create -f <model.qiy> -n <project-name> -o <empty-directory>`. This creates the full Turborepo + Bun project.
- Existing Bun project: put optional aliases in the model's `workspace` block, then run `qiy init -f <model.qiy>` from the existing project root. This mounts packages without adding Turborepo.
- Existing generated standalone project: use `qiy generate <model.qiy> <directory> --sync` only when maintaining a workspace previously generated by Qiy. Prefer `create` for first generation.

If the user has no model, start from the complete modular example at [examples/warehouse-admin/README.md](examples/warehouse-admin/README.md). It includes every `.qiy` file needed to generate a warehouse admin.

For a first-time user, prefer the warehouse example over inventing a model from scratch. Have them copy the whole example directory, run the exact generation commands, inspect the generated project, and then customize one entity at a time. Do not tell them to copy only `app.qiy`; its includes are required.

## Install this skill (for the agent environment)

The CLI bundles this skill offline:

```bash
# Current project: <project>/.agents/skills/qiy
qiy skill install

# User-level: ~/.agents/skills/qiy (for agents that load global skills)
qiy skill install --global

# Any agent-specific skills directory
qiy skill install --dir .claude/skills/qiy
qiy skill install --dir ~/.codex/skills/qiy

# Update official files after a Qiy upgrade
qiy skill install --force
```

Repeating an install preserves unrelated files and refuses locally changed official files; `--force` replaces only official files. Existing projects that still have the legacy `.agent/skills/qiy` directory are updated in place. A downloadable copy is published at `https://ai-nodev.github.io/qiy/skills/qiy/SKILL.md` (and `.../qiy-skill.tar.gz`); when the agent supports file URLs, prefer the CLI so versions stay aligned with the installed Qiy binary.


## First run

The CLI can install this complete official Skill offline: run `qiy skill install` from the user's project directory. It writes `.agents/skills/qiy/SKILL.md`, references and the full modular example. Repeating installation preserves unrelated files and refuses changed official files; `qiy skill install --force` explicitly replaces those files. Use `--global` for `~/.agents/skills/qiy` or `--dir <path>` for an agent-specific skills directory.

Generated projects include OpenWiki documentation and an `AGENTS.md` entrypoint, with `AGENT.MD` as a compatibility pointer. Standalone projects place them at the root; `init` places the agent entrypoints in the generated Web package and documentation in `openwiki/qiy-<admin-name>/`, preserving host instructions. Read the generated quickstart before changing application code; it lists the actual package paths and scripts, including aliases. These files describe generated capabilities, not production validation.

1. Check that Qiy is installed with `qiy --version` and inspect supported commands with `qiy --help`. Installing this Skill does not install the Qiy CLI.
2. If the CLI is missing, download the matching Windows, Linux, or macOS executable from the [Qiy GitHub Releases](https://github.com/AI-NoDev/qiy/releases), make it available on `PATH`, and retry. For a Bun project checkout, `bun run qiy -- --help` runs the local CLI.
3. Generate, install dependencies, and run the generated project using the workflow in [CLI workflows](references/cli-workflows.md).
4. Run typecheck, tests, and build before treating generated output as usable. `preview` is local-only.

## Generated project at a glance

Standalone `create` produces a Turborepo + Bun workspace. The main edit points are:

```text
apps/server/src/modules/    API contracts, repositories, services and routes
apps/server/src/db/         Drizzle schema and database connection
apps/server/tests/          API tests
apps/web/app/               Refine resources, routes, components and providers
deploy/                     Docker, Nginx, Kubernetes and platform examples
```

Use this map as orientation, then inspect the actual generated tree because enabled features and template versions can add or omit files. Generated TypeScript is intended to be edited. For long-lived custom behavior, prefer separate modules/hooks/plugins and keep generated files listed in `.qiy-generated.json` unchanged; `--sync` may rewrite or remove owned files.

## Typical follow-up tasks

- Add a table or field: edit the `.qiy` model, regenerate/sync, review the database migration, then update application-specific validation and tests.
- Change menu or field presentation: edit `menu`, `dashboard`, entity/field annotations, then regenerate.
- Add an explicit business operation: define the server transaction with `dataflow`, then expose it with an `action` using `placement list, show`. Qiy injects the current record id and generates inputs for remaining required command fields. Add `when status == "pending";` or `when status != "closed";` to show the action only for matching Text/enum records.
- Add a complex non-CRUD page: define an `action` with `navigate` and `page manual @comment(...)`, then implement the preserved file under `apps/<web-alias>/app/extensions/`. Qiy does not overwrite extension files during `create --sync` or `init --sync`.
- Connect a real database: set `DATABASE_URL`, generate and review migrations, apply them in the target environment, and test rollback/backup procedures.
- Connect an existing API or identity system: use an explicit adapter for its routes, response envelope, token/cookie rules, claims and authorization. CORS alone does not adapt API contracts.
- Deploy: choose the generated target as a starting point; configure secrets, TLS, health checks, durable storage, backups, observability and rollback for the actual platform.

Generated CRUD does not infer domain workflows such as approvals, synchronization queues, connector authorization or audit policy. Put those rules in server-side domain services and test them independently.

## Business action example

```qiy
dataflow revokeConnector @label("Revoke") @confirm("Continue?") @comment("Revoke an active connector") {
  input {
    field connectorId UUID @required;
    field reason Text @required @comment("Reason supplied by the operator");
  }
  context {
    connector = entity connectors by id input.connectorId @required;
  }
  step revoke {
    update connector { status = "revoked"; }
  }
  result { return connector; }
}

action revokeConnector {
  resource connectors;
  dataflow revokeConnector;
  placement list, show;
  when status == "active";
}

action reviewConnector {
  resource connectors;
  navigate "/connectors/:id/review";
  placement list, show;
  label "Review";
  page manual @comment("Implement the review workflow here");
}
```

Dataflow actions are fail-closed: the generated DataProvider only posts to declared command URLs. A Dataflow can provide default `@label`, `@confirm`, and `@comment` metadata; its Actions inherit label/confirmation unless they explicitly override them. Navigation actions require an absolute safe route containing `:id`. A `when` rule accepts only one current-resource Text/enum field, `==` or `!=`, and a quoted value; missing record fields hide the action. Keep authorization and state changes on the server even when a generated button is hidden by a condition or Refine access control.
